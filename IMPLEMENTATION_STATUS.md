## Known limitations (Phases 0–7, by design or environment)

- **No live PostgreSQL verification anywhere.** API and worker health
  logic is tested with the DB down (honest `unavailable` path); the
  `db: ok` path is exercised only in CI (Postgres service) and has not
  been observed live yet. Migration 0002 applies to Postgres in CI;
  locally the same schema is exercised via `create_all` on SQLite.
- **CI:** first runs observed failing on 73fb96d (2026-11-14). Two
  jobs failed: (1) python — the Phase 0 worker tests assumed no
  database exists, but CI runs a Postgres service, so
  `test_status_reports_db_unavailable_without_postgres` saw `db: ok`
  (pre-existing Phase 0 failure, same step failed on 8216b35); fixed
  by forcing an unreachable `DATABASE_URL` in those tests.
  (2) web — `biome check` failed on the new generated
  `packages/api-client/src/types.ts` and the new docs files; fixed by
  making the generator emit Biome-style output and formatting the
  docs files. Re-verified locally (`biome check .` clean); CI
  observed GREEN on the Phase 7 final push — Actions run 43626409634
  for `4261a02` (python, web, docs all success).
- **Docker images unbuilt.** Dockerfiles are standard `uv`-based images
  but `docker build` was never executed here (no daemon in sandbox).
- **Web health panel verified via prerendered shell + preview only.**
  The client-side fetch (React Query against the live API) needs a
  browser run with both servers up; the code path is the standard
  `fetch('/api/v1/health')` through the Vite dev proxy.
- **Phase 5 (Four Studios) built 2026-11-14 — no real-browser run.**
  All seven Studio pages returned 200 from `vite dev` and every data
  endpoint returned real data via curl (including through the Vite
  `/api` proxy), but no browser automation exists in this sandbox, so
  client-side rendering, canvas playback and the ECharts curve were
  verified by Vitest component tests + the proxy smoke, not by a
  browser screenshot. Responsive breakpoints (375/768/1024/1440) are
  likewise unobserved in a real viewport.
- **Backend gaps the Studios surface honestly (future work, not
  Phase 7 scope):** no training resume; no logs/resource-usage
  endpoint; no scenario-comparison endpoint; no department/tasks
  model; no update-experiment endpoint (config edits apply to the
  next run); PublishEvaluationReport and PublishPolicy
  approval-gated and unwired. **Closed in Phase 7:** list endpoints
  for experiments, evaluations and episodes; training-history
  endpoint; artifact-bytes/download endpoint. The episode and
  evaluation pickers are not yet wired to the new list endpoints
  (the endpoints exist; the UI wiring is a follow-up).
- **LangGraph 1.x upgrade outstanding (Phase 7 audit finding).**
  `pip-audit` reports 11 vulnerabilities in langgraph 0.6.8 /
  langgraph-checkpoint 2.1.2 / langgraph-sdk 0.2.15 (fix: LangGraph
  1.x). Not upgraded in Phase 7 — major-version bump, own
  verification needed. Syrius uses only the in-memory MemorySaver
  checkpointer and no langgraph-sdk auth decorators, so the reported
  attack prerequisites do not apply to the v0.1 shape.
- **JS dependency audit missing.** `pnpm audit` cannot reach the npm
  registry audit endpoint from this sandbox (request timed out);
  `npm audit` needs an npm lockfile the pnpm workspace does not
  have. No JS audit result exists for v0.1.
- **Random baseline mean is not stable across processes** with the
  same seed 0: 23.35, 22.30, 21.90, 20.85, 20.30, 16.95 across six runs on
  2026-11-14. PPO training (134.44) and evaluation (498.70) are
  identical every run. The baseline is always reported as measured;
  the Phase 7 E2E test asserts it only as `< 100`.
- **`check_env` warnings are Gymnasium's own** (infinite Box bounds,
  wrapper notice) and appear in logs; validation still passes.
- **Torch is the CPU build (2.15.0+cpu)** — the PyTorch CPU index
  source only applies when torch is a direct dependency (verified);
  the CUDA build was replaced, no NVIDIA packages remain.
